# 会话接力 Session Relay

会话接力是一个 DSH 插件。模型回复数达到设定阈值后，它在安全边界调用当前会话的 `compactRegion` 压缩历史，创建一个真实的新会话，迁移摘要和未处理输入，并按设置继续长任务。旧会话保留，后续发送到旧会话的输入会继续转发到接力目标。

插件默认关闭，默认阈值为 **90 次模型回复**。适用于 DSH `>=0.2.2-rc.5 <0.3.0`、Node.js `>=24`。当前 Agent 预设或全局环境需要提供压缩服务；没有服务时会停住并显示错误。

## 启用与设置

安装或更新本地插件后，打开 **DSH 设置 → 会话接力**，开启“启用自动接力”，设置触发模型和回复阈值，再保存。无需先打开会话；会话输入框旁的面板仍可查看进度、修改同一份设置和恢复失败的接力。子代理会话不自动接力。

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 启用自动接力 | 关闭 | 达到阈值后开始接力 |
| 模型回复次数阈值 | 90 | 可设为 2–10000 的整数；每个新会话重新计数 |
| 触发接力的模型 | 留空 | 留空时不限模型；否则填写精确模型 ID 或 `provider/model`，多项用逗号或换行分隔 |
| 长任务中断时自动继续 | 开启 | 在工具循环的安全边界被切换时，向新会话发送一次续接指令 |
| 完成后自动打开新会话 | 开启 | 当前面板观察到接力完成时打开目标会话 |

模型筛选以接力时正在使用的模型为准，不改变会话的模型选择。同一模型 ID 有多个供应商时，可用 `provider/model` 只允许其中一个。

计数以 DSH 记录的 `assistant/message` 为准，**包含模型发出工具调用的回复**；工具返回的 `tool/result` 不再单独加一次。计数是会话内模型回复数，不等于供应商账单中的全部请求数。

压缩会在工具调用与结果配对完整的边界进行。任务仍在运行且已开启自动继续时，新会话沿用上一个会话的模型和推理档位，达到阈值可以再次接力。正常完成的任务只建立新会话，不无故创建新的续接任务；已有未处理用户输入则会优先迁移并唤醒目标会话。摘要与原输入均使用稳定消息标识，重试时会核对目标的持久接收记录，覆盖已认领但尚未写入对话的窗口。

## 命令

命令直接执行，无需让模型额外回复。

```text
/relay status
/relay on
/relay off
/relay set 90
/relay retry
/relay release
```

- `status`：查看计数、设置、接力阶段、目标会话与错误。
- `on` / `off`：开启或关闭新的自动接力。关闭不会丢弃已经开始的接力记录。
- `set 90`：修改回复阈值。
- `retry`：用已保存的摘要与目标标识重试迁移，不重新请求摘要。
- `release`：在尚未创建目标的失败状态下停用自动接力，把已认领输入恢复到旧会话收件箱。恢复本身不自动运行模型；发送新输入后继续。

也支持 JSON 请求，例如：

```text
/relay {"action":"configure","settings":{"threshold":80,"modelFilter":"my-provider/my-model","autoContinue":true,"autoSwitch":true}}
```

插件同时提供 `session_relay` 工具，支持 `status`、`configure`、`retry`、`release`。只有在用户要求时才应通过工具修改设置。

## 失败与恢复

摘要、持久化或迁移失败时，旧会话停止调用模型，保留接力记录与未处理输入。面板会显示错误；已有可用摘要时可以“重试续接”，尚未创建目标时可以“停用并恢复未转移输入”。目标已经创建后，请在目标会话继续，不能把同一批工作释放回旧会话重复执行。

重启或重新加载插件时，未完成的中间阶段会转成明确的暂停错误，等待人工重试或释放，不自动重放工作。新会话的续接标记和唤醒时产生的收件箱变更持久化后，才清空旧接力记录。后续发往已接力旧会话的输入仍按原始消息标识转发。

## 配额与会话边界

若供应商每个会话允许约 100 次回复，建议阈值设为 **80–90**，为摘要和失败重试留出余量。摘要请求、失败请求和请求重试可能消耗额外额度；阈值不是精确的供应商配额计数器。

创建新会话只改变 DSH 的会话身份和上下文。按账号、密钥、时间窗口累计的额度不会因此重置，是否能继续取决于供应商规则。

新会话保留工作目录、Agent 预设和模型选择，并接收压缩摘要及未处理输入。**子代理、后台任务句柄、临时授权和进程内执行状态不迁移**；旧会话中的后台工作可能仍存在，需要回到旧会话核对。续接指令会要求先检查实际文件和执行结果，避免重复已有操作。

## 本地验证

```sh
npm test
npm run check
```

纯协调器测试无需 DSH 依赖。Adapter 测试使用本地结构替身，不调用真实模型或业务服务；有 `DSH_INSTALL_DIR` 时会同时核对安装版模块导入。桌面版 ASAR 环境可使用运行时自带的 Electron：

```sh
ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" --test test/*.test.js
```
